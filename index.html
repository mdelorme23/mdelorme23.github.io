Mocap Shoot Interface
PythonTkinterSQL
I developed a stand-alone python graphical interface using Tkinter to centralize data management and recording during motion capture shoots into a single tool. Take data, associated assets, filenames, and all pertinent details are saved in an SQL database accessed by both the tool and the post-production pipeline. The tool ensures unique take names across a project and allows assets from previous shoots to be imported during prep.

The tool connects to multiple capturing devices in order to trigger recording on all of them at the same time. It also saves each take information from these capturing devices in its database. It connects to a large range of devices: motion capture software, reference videos recorder, head mounted camera systems, DCC and game engine. It ensures integrity between assets name in its database and the connected software to remove naming disparity during the rest of the pipeline.

A web interface is also available to allow multiple users to view live shoot data as it progresses. Users can update a limited set of fields relevant to their expertise, and a comprehensive action log tracks all changes made during the shoot.

The data and reports are exported in various formats for members of the team. It is also sent to Flow PTR (ShotGrid) and the Client Selection Website with the videos. The reference videos are processed as soon as possible to allow the client to make data selection in the next hour if needed. The video compression (through FFmpeg) and data upload sections of the tool were initially combined in the main interface, but they were separated for stability and increased processing power.
